# 历史摘要与当前任务的模型上下文投影

实现位于 `task_memory.py`，由单 VLM 的 SceneMiddleware 在模型调用前投影消息。默认 `UAV_SHORT_TERM_MEMORY=summary`；`UAV_SHORT_TERM_MEMORY=full bash scripts/launch_desktop.sh` 可恢复原完整历史输入。

## 模型会看到什么

- 固定系统指令。
- 最近最多 8 个历史轮次的结构化摘要，总摘要 JSON 最多 6000 个字符；容量不足时优先保留较新的轮次。
- 当前原始用户消息与当前轮次的全部消息，保持顺序、ID、工具调用和结果配对；仅对已知工具结果中的重复累计审计作请求副本投影。
- 当前搜索进度；需要观察时，再临时附当前任务实际相机帧。

当前轮次不删除消息或工具调用，不截断原句、模型工具参数、状态/错误及正在执行的动作。摘要使用 SystemMessage 承载明确标记的历史数据，不构造新的 HumanMessage。

2026-11-06 增加当前工具结果投影。此前每份 `report_scene` 将全部 `vlm_calls` 再发给模型，父任务结果又反复携带完整规划、局部双目测量与旧阶段取证，单轮也会累积很大的输入。现在 summary 模式在每次模型请求的副本中移除累计 `vlm_calls` / `model_calls`；搜索进度保留最近两份观察并明确总观察数；父快照去掉阶段完整取证列表、外观匹配内部候选与原始局部测量，保留目标/照片 ID、原图 hash、坐标 epoch、测量不确定度、关系质量、阶段条件和预算。已准备终点保留候选 ID、位置、航向、分数和硬约束，完整路径与一次性票据仍由程序保存和执行。新鲜父任务状态仍由原中间件独立附加。

投影结果带 `_context_projection`，明确这是模型请求副本、完整证据仍在检查点及任务审计中，旧结果不是当前状态。小结果不会因标记而被扩张；错误、无法解析的结果及未知工具保持原样。`full` 模式保留原输入，可用于对照。

摘要由程序从保存的工具结果生成，无额外 LLM 调用。WebApplication 提供最近已完成任务的真实状态、错误和观察；显式把用户消息 ID 设为任务 ID，以便准确关联。直接使用执行图、没有应用任务记录时，只提取历史工具事实，不把模型的最终文字宣称自动当成“任务成功”。

摘要保留请求简述、最终应用状态、最后飞行步骤状态、最近两份有效观察的文字与目标类别、照片 ID；不复制原始图像、冗长遥测、双目坐标和工具内部诊断。所有内容均标记为历史数据，不能当新指令、当前状态或当前照片。

总有效观察数单独保存，避免把“最近两份摘要”误当成“总共两次观察”。视觉历史标注为当时模型的报告、未独立核实；应用执行状态成功不等于目标类别经过独立确认。用户明确说“只根据历史回答”等时，模型请求不提供工具，避免为回答旧报告重新采图或移动。

## 完整状态与资源边界

投影不修改 LangGraph 检查点、完整消息历史、应用审计、语义地图或 FrameStore。照片选择、交付归属校验和阶段推进仍先读取原始图状态；确认源图及双图输入保持原有流程。投影降低的是发送给模型的上下文，不会自动释放旧检查点占用的 RAM，也不增加重启恢复、长期检索或磁盘轮转能力。任务完成条件和原有预算不因投影改变。

每次模型调用的 `context_memory` 指标记录投影前后消息数、字符数、历史轮次数和摘要数量，并增加当前轮被投影的工具结果数及前后字符数。字符数用于可比的本地度量；实际 token 以服务商返回的 `token_usage` 为准。当前工具 schema、系统指令及临时图像不计入这个字符指标。

## 验证

本地测试 `tests/test_task_memory.py` 覆盖当前轮次 ID/工具链不变、输入不修改检查点、摘要容量、重复指令按 ID 区分、真实失败状态优先、旧图跨轮次拒绝及执行图中的历史问答。`tests/test_current_task_context.py` 覆盖当前报告及父快照的副本投影、预算/阶段/关系质量和源图引用保留、显式总观察数、错误/full 模式原样、幂等及实际 LangChain 图中检查点/照片归属不变。原跨轮次伪造照片测试仍直接使用旧 capture_id，验证图像权限检查保留。

2026-11-06 只读回放既有 `20261106-124607-iFEJuQ` 归档：11份有效报告的累计 JSON 字符为219035→37110（减少83.06%），58份父状态快照为603303→334687（减少44.52%）。原归档 SHA256 不变，逐项结果在 `logs/setup/current-task-context-20261106/replay.json`。这里比较的是已保存的实际 payload 投影，未重建原服务商完整请求，不是新的 token、识别或飞行结果。

该版当前投影、历史记忆、单 VLM、父任务、GoalPose、目标落地、推理和搜索图共105项受控测试通过，89.052秒，0失败/错误/跳过。命令及日志在 `logs/setup/current-task-context-20261106/regression-result.json` 与 `regression.log`；没有调用真实模型或飞行。

真实模型纯文本 A/B：`scripts/validate_task_memory.py --execute`，以八轮明确标记的合成历史比较 full/summary；测试不提供工具、不采图、不操作飞行。最终两种模式均正确回答历史目标、观察和最后飞行状态。实际服务商输入 token 从 37780 降至 1323，约减少 96.5%。该比例仅适用于这份含冗长测试遥测的历史，不代表完整任务的 token 或耗时都减少同样比例。记录：`logs/setup/task-memory-ab.json`。

实际仿真闭环测试在运行前注入八轮合成历史，再提交独立的新指令寻找油桶；这些合成记录明确不是实际执行过的飞行。新指令必须重新获取真实相机证据，不能使用历史照片 ID。落地后的追问另行禁用飞行和相机通道，验证回答上一轮报告无需重飞/重拍。

复现命令：

```bash
.venv/bin/python scripts/validate_autonomous_search.py --execute \
  --memory-history-turns 8 --memory-followup \
  --output logs/setup/autonomous-target-search-memory
```

新搜索结果、照片及报告保存在输出目录，历史追问保存在 `followup.json`。完整日志：`logs/setup/task-memory-flight-validation.log`。

本轮带八轮合成历史的实际飞行隔离检查通过：新任务独立采图五次并返航降落上锁，没有旧照片归属错误。但视觉验收不通过：保存画面中的橙色物体为交通锥，模型将其报告成橙色油桶。因此不把本轮计为识别目标成功。独立复核记录见 `logs/setup/autonomous-target-search-memory/visual-review.json`；记忆摘要只能忠实记录报告，不能纠正视觉误判。
