# 检测框盲审实验

这个离线实验检验一个具体假设：复核者只看检测框内的真实像素、且事先不知道原目标名称时，是否更容易发现原报告把墙面或交通锥误标为货车或油桶。它不飞行、不更新地图，也不是生产目标确认规则。与原始双图复核相比，这仍是同一个供应商和模型，不能视作独立模型证据。

`scripts/review_blind_crop.py` 读取已有任务报告和原图，校验原图 SHA256 及历史图像已送达模型的记录，严格依据报告框裁图；模型仅接收该裁图及通用提示，不接收目标名称、整图、原框坐标或原结论。记录保存原图、裁图、哈希、模型响应、提示版本和耗时。裁图仍是原照片的派生图，不是新视角。运行时必须显式加 `--execute`，会将裁图发送至现有模型；不要将模型输出当作经标定概率。

结果保存在 `logs/setup/blind-crop-20261102/`，均来自已归档的实际 Gazebo 相机图像：

| 案例 | 观察结果 | 应如何解释 |
| --- | --- | --- |
| 灰墙被原报告误标为货车 | v1 三次选择墙，v3 无可辨认类别 | 此裁图盲审没有复现原误报，不能推广为灰墙误报率 |
| 曾被原报告误标为油桶的交通锥 | v1 选油桶但文字描述交通锥；v2/v3 选交通锥 | 单选类别集合会诱导错误分类，文字与类别也可能不一致 |
| 同框中车辆局部及交通锥 | v1 选车辆；v2 只选交通锥；v3 同时返回车辆和交通锥 | 添加类别可引入漏报；多标签在此例更合适 |
| 两张原图中可见的小蓝色油桶 | v1 和 v3 均无法从小裁框识别 | 空结果不能解释为油桶不存在，也不能据此丢弃候选 |
| 另外三个已有车辆裁图 | v1 选择车辆 | 属于有限回放样本，未测类别错误率或跨视角同物体关联 |

`false-barrel/` 记录的是最初误选的同一报告第 0 个框（红色集装箱）；真实蓝色油桶误报为第 1 个框，证据在 `false-barrel-correct/` 和 `v3-uncertain/`。原始记录保留，不把错误框当作油桶实验。

这些案例被用于调整提示，属于开发集，不是独立测试集。尤其 v3 对真实小油桶和背景误报都可能返回空列表，无法区分“物体不存在”和“像素不足”；类别列表也不覆盖任意自然语言目标。即使两个裁图都返回目标类别，也没有解决是否为同一物体的问题。后续应先构建跨场景、遮挡、不同尺度的人工标注留出集，分别测量误报、漏报和不确定率；若将其用于主动观察，应把空结果作为继续靠近或换视角的线索，不能直接将当前搜索标记为目标不存在，更不能解除 `clipped_regions_v3` 的确认限制。

## 冻结图片的初步评估

[评估清单](evaluation/blind_crop_holdout_20261102.json) 在模型请求之前固定了 v3 提示哈希和 10 张原图的哈希，检查每张图片均不在上面的开发图片中。这是**图片级留出**，并非场景级或任务级留出：照片来自两个已有仿真世界，有相似布局和相邻视点。框及是否可见由本次助手查看图片标注，尚未经独立人工复核；没有油桶正例，不能用于评价油桶召回。

10 次实际模型请求的结果：4 个车辆正例均返回 `vehicle`；1 个小交通锥正例返回空列表；5 个负例均未返回对应待测类别，其中部分返回空列表。总共 3 个空列表。模型请求耗时中位数约 4.94 秒、合计约 48.14 秒，不含飞行和后续复核开销。这是刻意挑选的小样本，不能据此估计可靠的误报率、漏报率或生产性能；“未返回目标类别”也不是模型明确判断目标不存在。

原始输入、逐条响应和[汇总](../logs/setup/blind-crop-holdout-20261102/summary.json)已保存。`scripts/evaluate_blind_crop_holdout.py` 支持 dry run 和显式 `--execute`；恢复模式校验冻结清单、提示、原图和重新计算的裁图哈希，避免把不同内容当作同一案例，也不会重新请求已有完整案例。此次没有飞行，也没有将人工选择的离线评估框或标注接入生产地图。
