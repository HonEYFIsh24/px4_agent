更新日期：2026-10-04。**当前状态：run6 完成基础自主绕障往返，run9 完成采图、红箱报告、自主绕障返航与降落，两项独立验收均通过。** 两次实际采样折线最小碰撞净空分别为 `1.483502 m` 和 `1.499739 m`，高于保持不变的 `1.0 m` 验收门限；六类状态 / 传感器分别为903/903和954/954有效。run7返航被感知地图拒绝；run8的 `return_home` 多余字段被拒绝，未执行返航，在目标点附近降落上锁。软净空规划、代价保留路径简化、阻塞起点静止等待和严格五动作工具 schema 已实施；run9未触发8秒等待分支，该分支仍只有离线回归覆盖。7次失败指令全部保留，其中6次实际飞行未完成、1次模型连接异常未起飞。

## 1. 能力范围

单 VLM `qwen3-vl-plus` 理解任务并调用受限飞行 / 视觉工具。使用者只指定目标点；执行器根据实际机载 LiDAR 测量生成中间路线。Agent 不读取障碍物模型位置或预置绕行路径。

当前能力是 **固定本地 ENU 高度 `3.5 m`、静态障碍、二维平面导航**。没有验证三维飞越、动态障碍预测、GPS 拒止 VIO 飞控闭环或任意环境导航。VINS-Fusion 继续使用双目与原机体 IMU，作为独立状态输出；当前导航位姿来自 MAVROS，本次实现不会自动将 VIO 输入 PX4。

## 2. 传感器、地图与规划

- 真实 Gazebo 射线 LiDAR：360 个水平角采样、10 Hz 仿真频率，量程 `0.2–20 m`，话题 `/uav/lidar/scan`。
- 执行器限制当前二维建图射线到 `5 m`，避免机体倾斜导致远处射线越过高墙后错误清空平面障碍。
- 同步匹配本地 ENU 位姿；源测量年龄、现实接收年龄、固定高度、姿态与匹配误差由执行器独立检查。
- 使用同步的飞机自身 Gazebo 位姿监督实际 LiDAR 原点的世界高度，要求 `Z∈[2.5,4.3] m`；这项检查不读取障碍物坐标，规划地图仍由真实 LiDAR 与本地 ENU 位姿构建。
- 栅格分辨率 `0.3 m`，障碍膨胀至少 `1.0 m`，另加离散化余量；未知区域禁止直接通行。
- A* 在已测量允许区域寻路；目标尚不可安全到达时，可先到传感器确认安全的 frontier 前沿位置，取得新测量后重规划。
- 已实施软净空代价，使 A* 优先保留离感知障碍更远的合法路线；简化只接受不会明显增加该代价的连接段。硬允许栅格、未知禁行和净空门限保持不变。
- 每次只执行下一段可见安全路线；持续检查清障条件和 LiDAR 新鲜度。有效新地图使原段不再许可时，冻结设定点、记录感知网格并停止；物理水平速度 `≤0.15 m/s`、距离悬停目标 `≤0.15 m` 且持续 `1 s` 现实时间后，才对同一目标重新规划。源过期、无效扫描或高度监督失效仍使任务失败。
- 有效地图暂停并停稳后，若当前起点仍不属于允许区域，最多再静止等待 `8 s` 现实时间，继续接收新鲜有效扫描；自身保护范围连续 `1 s` 被观测为安全后才重规划。等待不移动、不主动清空 occupied、不降低门限；锁存的传感器故障、无效扫描或源过期立即失败，持续未知 / 占用到超时也失败。
- 导航暂停保留固定本地高度 `3.5 m`，水平设定点速度当前候选限制为 `0.25 m/s`，开始规划前需至少 5 帧有效扫描。降低巡航上限后的新完整飞测仍待验收；原停车速度、距离和超时门槛不变。当前35项导航专项检查已通过，含4项新等待行为检查；完整绕障实测仍以任务结果为准。

具体入口为 [`obstacle_navigation.py`](../obstacle_navigation.py) 的 `NavigationMap` 与 [`bridge.py`](../bridge.py) 的 `on_lidar()`、`start_navigation()`、`move()`。地图由测量射线更新，不接受世界实体真值。公开边界与固定高度来自运行 manifest，用于约束操作范围，不表示边界内已知无障碍。

`/api/state.navigation` 展示实际 LiDAR 是否有效、地图是否新鲜、扫描数量、最近观测障碍、地图已观测比例和最新计划。每个 mission 的 `navigation_plans` 保存目标、传感器来源、自动中间路径、frontier / 完整路径标志和时间，供审计真实绕行。公开 `navigation_pauses` 只保存停段位置、目标、传感器错误分类和地图摘要；**完整感知栅格另存本地 [flight.jsonl](../logs/flight.jsonl) 的 `navigation_paused` 事件**。新版本地网格另存命中格的扫描时间、射线与测量原点等来源证据，静止等待也写入 `navigation_clearance_wait` 事件。未知 / 占用 / 边界等具体原因需核对完整网格，不能仅从摘要或笼统错误文字推测；这些都是传感器测量取证，未读取障碍物真值。

长返航也需区分图像缓存与已保存报告：原 `FrameStore` 的 `180 s` 现实 TTL 会使已经报告过的旧帧在最终模型调用阶段触发准备错误。单 VLM 现已修改为同轮最新快照成功保存 `report_scene` 后，后续模型只依据保存报告，不再重复附该旧图；新快照、未报告、报告失败、送达及会话归属检查仍保持严格。相关 37 项单 VLM 本地回归已通过；run9最终纯文本调用距保存报告 `227.424183 s`，实际覆盖180秒之后的完整视觉返航流程，详见第7.9节。

## 5. 独立验收

首先检查 Agent 实际提交的 goto 只有用户目标或实际起飞点返航，禁止模型提供绕行中间航点。真正的绕行路径必须来自 mission 内审计的 `navigation_plans`，来源为 `horizontal_lidar_aligned_enu`，包含实际扫描数量、新鲜源时间以及自动生成路径。去程和返程都需真实完成计划与飞行事件。

净空评价在测试端读取 `obstacle_layout.json` 的 **`collision_aabb_world_m`**。不使用仅视觉包围盒，不将布局或预置可行路径传给运行系统。评价包括：

1. 使用实际起飞点及完成目标事件附近的新鲜 Gazebo 位姿建立世界坐标直线对照，保存原 ENU 指令与世界坐标取证。直线到两墙的碰撞净空均须不足机体加跟踪余量 `0.70 m`，证明有体积的无人机确实需要绕行；中心线是否精确相交另行记录，避免厘米级坐标偏移导致边界假阴性。
2. 保存 Gazebo 的真实机体中心世界位置；计算全部采样点与每两个连续采样之间完整线段到每个碰撞矩形的最短 XY 距离。
3. 分段二次函数求精确线段最小值，避免只检查端点而漏掉线段穿墙。
4. 核对实际轨迹在第一墙附近达到 `y>3 m`、第二墙附近达到 `y<-1 m`，没有爬升越墙；主要判据仍是实际几何净空。
5. 报告物理保护半径 `0.45 m` 加跟踪余量 `0.25 m` 的 `0.70 m` 下限，以及计划要求的实际 `1.0 m` 净空。若实际低于 `1.0 m`，独立记录短缺量，整项不能标为通过。
6. 保存全部传感器就绪比例及任一失鲜采样；建图开始前 / 降落后的 `map fresh=false` 与实际导航移动期间失鲜分开记录。

连续线段结果是对 **采样折线** 的几何评价。真实飞行在采样间可能为曲线，因此另报告最大现实 / 仿真采样间隔；该指标不等同于连续时间碰撞传感器证明。全部纯碰撞 AABB 均纳入 XY 检查，低于飞机的实体也被保守计入；本次固定高度场景不通过忽略碰撞物来增加通过率。

视觉工具成功与红箱识别单独评价。只有报告对应实际带图调用、快照新鲜且 hash 有效，才能认定观察流程完成；标签匹配仍需独立检查原始模型输入。没有深度时只报告画面位置和方向，不编造三维位置。

## 7. 当前结果

### 7.1 首次实际任务：边界净空拒绝

[run1 原始任务报告](../logs/avoidance/run1/autonomous_goal_round_trip/task_validation.json) 的 command ID 为 **`4e1f9c9f90784853`**，结果 `failed`，用时 `86.087 s` 现实时间，167 次完整状态采样。3 次 `qwen3-vl-plus` 接口调用均正常；失败来自实际规划器的运行边界检查，错误为 `goal lacks clearance from the permitted navigation boundary`。

当时世界 / ENU 水平朝向存在约 `0.04 rad` 偏差。执行器为防止旋转后的局部操作矩形越出世界边界，采用保守内接区域，实际 ENU `xmax=15.014658 m`。旧目标 `x=14 m` 到此边界仅约 `1.014658 m`，不满足 `visible_clearance_m=1.2 m`，因此在生成路线前被拒绝。起飞地图已取得有效扫描，实际扫描计数为 41、射线有效比例为 1.0；`last_plan=None` 表示没有批准任何路径，不能误读为 LiDAR 未工作。

任务仅完成起飞事件，没有完成 goto 或朝墙推进；独立执行器随后完成安全降落上锁。167 次采样的飞行状态、Gazebo 位姿、双目、独立 VIO 与 LiDAR 可用性全部有效。落地后地图停止更新的 `fresh=false` 属于 inactive 阶段，不代表持续工作的 LiDAR 源中断。原始任务仍标为失败，安全落地单独记录。

后续两条正式指令把目标改为 **`(13,0,3.5)`**，增加边界空间；没有改变操作边界、`1.0 m` 障碍膨胀、`1.2 m` 可见净空或独立实际轨迹最小 `1.0 m` 验收门限。新的目标仍在第二墙之后，直线路径仍受两墙阻挡，需要完成 S 形绕行。旧 run1 日志不修改、不覆盖，目标变化后的真实实验另存 run2。

第一次落地后，本地 ENU 地面高度与 Gazebo 世界高度出现偏差。固定 ENU 高度本身不足以保证物理 LiDAR 仍处于二维高墙的适用扫描平面。同步飞机自身世界位姿计算 LiDAR 原点高度 `Z∈[2.5,4.3] m` 的监督已部署，其 [22 项专项测试](../logs/avoidance_height_guard_tests.log) 通过；它不向规划器提供障碍物真值。后续每次起飞仍需实际预检，不能用单元通过替代成功绕障证据。

### 7.2 run2：第一自动段被安全门限取消

[run2 原始任务报告](../logs/avoidance/run2/autonomous_goal_round_trip/task_validation.json) 的 command ID 为 **`a09e45291b874034`**，最终 `failed`，用时 `62.504 s` 现实时间、123 次完整状态采样。3 次模型接口调用均正常，执行错误为 `LiDAR navigation clearance/freshness gate closed; holding`。没有到达目标、没有完成 S 形通行或返航；独立执行器已完成安全降落上锁。

首个实际导航计划使用 `scan_count=1`、新鲜测量，产生自动 frontier 点约 `(2.6005,2.1591)`，原 goal `(13,0,3.5)` 未改。执行中后续扫描更新了地图，原段重新检查不再通过；旧实现立即悬停并令任务失败。原记录没有停段感知网格，**尚不能可靠确认是哪一个 unknown、occupied 或 boundary 单元导致关闭**，不把笼统门限错误解释成已经识别到某一具体障碍。

实际轨迹仅推进到世界 `x≤1.6415 m、y≤1.3840 m`，独立采样折线最小碰撞净空为 **`2.358541 m`**。这说明被记录的局部轨迹保持了几何距离，没有完成目标的事实仍使实验失败。[轨迹评价](../logs/avoidance/run2/autonomous_goal_round_trip/trajectory_evaluation.json) 报告最大采样间隔为 `0.562647 s` 现实时间 / `0.528 s` 仿真时间；尚未到达目标，真实起点到实际终点目标的直线对照被明确记为 unavailable。

传感器证据也存在限度：飞行状态、Gazebo、左右相机与 LiDAR 均为 **123/123** 可用，28 个实际导航移动采样的地图均新鲜；独立 **VIO 为121/123（98.374%）**，在安全降落末段的索引114和115报告初始化 / 重置 / 跟踪状态过期，原样记录在失败报告中。VIO 没有用于飞控，不能据此隐去这两次失效。

run2 的重启未继承 `gui=true`，使用了无图形界面模式，后续 run3 恢复 Gazebo GUI 并使用 `sim_speed_factor=0.35`。这项实验条件差异单独记录；现有证据不足以认定它导致了门限关闭。

### 7.3 run3：暂停过程中高度累积偏移，扫描被拒绝
