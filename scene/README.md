# 小型物流园区 Gazebo 场景

这是本项目自建的 Gazebo Classic 物流园区，替代早期由彩色图案和特征墙组成的 VIO 演示环境。场景用当地面、道路、停车位、货运设施和办公建筑构成有实际语义的巡检任务。所有纹理和几何均在本地生成，不依赖外部模型下载。

## 文件与生成

```bash
cd /home/dut/px4_agent
/usr/bin/python3 scene/generate_world.py
gz sdf -k scene/worlds/logistics_yard.world
```

生成器需要系统 Python 的 `numpy`、`cv2`，现有 ROS 环境已经具备。随机种子固定为 `20261004`，重复生成得到相同场景和纹理。

| 文件 | 用途 |
| --- | --- |
| `generate_world.py` | 程序生成纹理、实体几何、场景配置并检查净空 |
| `worlds/logistics_yard.world` | Gazebo 加载的 SDF 1.5 世界 |
| `materials/scripts/yard.material` | OGRE 材质定义 |
| `materials/textures/*.png` | 沥青、草地、砖、混凝土、木材、树冠、建筑招牌 |
| `runtime_manifest.json` | 公开场景约束：世界文件 SHA256、地面平面、飞行区域；没有目标真值 |
| `layout.json` | 独立评价用真值：实体位置、尺寸、包围盒和任务候选；不得输入 Agent 或 VLM |

材质引用生成目录的绝对 `file://` 路径；移动项目后重新运行生成器。Gazebo 资源路径包含项目 `scene` 目录。唯一 `model://` 引用是 Gazebo / PX4 安装自带的 `sun`。

## 场景布局

世界 XY 范围为 `[-20,20] × [-20,20] m`。路面及草地、混凝土视觉表面共用近似地面高度 `z=0.003 m`，道路油漆只是薄视觉层。地面实体有碰撞，其他主要实体也具备碰撞几何。

原点是画有 H 的起降区，机头沿世界 `+X`，左右相机保持原有 `0.35 rad` 俯角。东侧设施适合在指定航点从机载相机观察，无需增加转向工具。

| 设施 | 世界坐标中心，m | 可见特征 |
| --- | --- | --- |
| 红色货运集装箱 | `(13,-2,0.003)` | 约 6 m 长，沿 Y 放置；红色波纹墙、角柱、双端门和锁杆 |
| 白色配送厢式车 | `(13,3.5,0.003)` | 车头朝西；驾驶室玻璃、黑轮胎、轮毂、保险杠、前后灯 |
| 两个蓝色金属圆桶 | `(10.8,0.7,0.003)`、`(10.8,1.6,0.003)` | 蓝色圆柱桶身、加强箍、顶盖 |
| 橙白交通锥 | `(10.5,-4.8,0.003)`、`(12,-5.7,0.003)` | 黑底座、橙白相间锥体 |
| 砖结构仓库 | `(15,-11,0.003)` | 窗、卷帘装卸门、装卸区护柱、仓库招牌 |
| 两层办公楼 | `(16,11,0.003)` | 窗框、玻璃入口、办公楼招牌 |
| 周边环境 | 园区外围 | 草地、树、灯杆、栅栏、装纸箱的木托盘、路边线和停车位 |

净空观察走廊是世界坐标 `x∈[-3,8]`、`y∈[-4,4]`、`z∈[0,6]`。公开运行约束还保留 `0.6 m` 飞行边界余量，因此测试航点选在走廊内部。所有非地面碰撞实体在该净空走廊之外，生成器对每个记录实体检查至少 `2 m` 水平净空距离。建筑实体不安排在观察路径上。

颜色、窗户、车轮、波纹和材料纹理共同提供视觉语义；沥青裂纹、石粒、砖缝、油漆线及不同深度的设施为 VIO 提供可跟踪特征。该模型是离线、可复现的几何仿真场景，实体识别与定位结果仍以实际相机画面及任务验收为准。

## 自然语言任务候选

以下 ENU 航点假设 Iris 在世界原点、零朝向生成。正式执行前由桥接器核对 MAVROS 位姿与世界坐标关系；Agent 接收的是用户指定航点及目标描述，不能读取上面的实体真值表作为视觉答案。

1. **定点设施观察**：起飞到 3.5 米，飞到 ENU 坐标 `(5,-2,3.5)`，保持位置观察前方，寻找红色货运集装箱，报告它的位置方向和周围物体，然后返航并降落。
2. **车辆两次复查**：起飞到 3.5 米，先去 ENU `(5,3,3.5)` 观察白色货车及停车区，再沿原高度到 `(7,3,3.5)` 重新观察并比较两次结果，返航降落。
3. **两个观察站点巡检**：起飞到 3.5 米，按 ENU `(5,-2,3.5)` 和 `(7,0,3)` 两个站点巡检，每站悬停拍摄。第一站找红色集装箱和锥桶，第二站找蓝色圆桶并描述附近车辆、建筑，全部观察结束后返航降落。

前两类设施是凸起实体，直接根据其图像中心投影到地面会产生错误距离。模型识别后，程序仅在明确可见接地证据等适用条件下输出地面近似位置；其余情况报告图像区域与视线方向。场景真值仅用于独立比较，不能代替图像识别。

## 静态验收

生成器已执行 XML 解析、全部 23 个设施实体的净空检查；`gz sdf -k` 返回 `Check complete`，无 SDF 警告。仿真物理参数保持 PX4 `empty.world` 的 250 Hz / 0.004 s 步长和磁场参数。飞控、原 IMU、立体相机与 VINS-Fusion 的配置由项目原有启动程序负责，场景生成器不修改这些文件。

实际 Agent 调用、航点飞行、视觉报告、图形界面和最终落地状态的记录由系统验收流程保存；本目录中的任务候选不代表已经完成飞行。

## 独立的自主绕障场景

`scene/generate_obstacle_world.py` 另行生成 `worlds/obstacle_yard.world`、`obstacle_manifest.json` 与 `obstacle_layout.json`，不会改写以上物流园世界或其 manifest。运行方法：

```bash
/usr/bin/python3 scene/generate_obstacle_world.py
gz sdf -k scene/worlds/obstacle_yard.world
```

新场景允许在 `x∈[-3,16]`、`y∈[-8,8]` 范围以固定 ENU `3.5 m` 高度使用二维激光网格导航。两道主墙分别位于 `(4.5,-2)` 和 `(9.5,3)`，厚 `1 m`、沿 Y 长 `8 m` 与 `6 m`、高 `5.5 m`。其南端及北端各有高货柜块连接到许可区边界，因此到达东侧目标需要实际绕过第一道墙的北端，再绕过第二道墙的南端。另有三根同样高 `5.5 m` 的独立设施柱。

许可区域内的碰撞实体全部覆盖运行时约 `4 m` 高度的水平激光扫描平面。货车、集装箱、蓝桶、锥桶、树木、托盘和办公仓储设施的实际碰撞包围盒全部在该 XY 区域外，避免低矮物体落入固定高度扫描的盲区。原点半径 `1.5 m` 的起降通道在地面至 `6 m` 内没有障碍。

生成器根据实际 SDF 的碰撞组件检查物理交叠：58 个组件中没有非预期的跨模型包围盒交叠；仅保留外围栅栏的两个结构性角连接。独立评价用 S 形可行路径的水平净空保守下界为 `1.75 m`，相对 `1.2 m` 地图膨胀仍留 `0.55 m` 余量。可行路线仅保存在 `obstacle_layout.json` 中，Agent 和规划器不得读取该文件。

建议直接给 Agent 的目标是 **ENU `(14,0,3.5)`**，例如：“起飞到 3.5 米，自主绕开障碍到 ENU 坐标 `(14,0,3.5)`，到达后悬停观察前方并报告可见物体，再自主返航并降落。”不向 Agent 提供人工绕行航点。公开 `obstacle_manifest.json` 只提供场景指纹、地面和运行边界、激光导航参数及起降区域许可。
